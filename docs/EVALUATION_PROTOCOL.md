# Personal Agent 真实评测协议

本协议把产品可用性、事实核查、记忆能力与资源用量分别记录。不得把运行成功、模型自评分或来源 ID 存在改名为“事实正确率”。

## 样本与对照

- 两个真实研究配对样本：同一个亦伴项目背景，分别使用 Hermes Agent 与 nanobot 官方仓库，完成机制研究/价值判断与可纠正记忆的需求草稿。每个配对内使用同一竞品、同一任务和同一来源快照。
- 原版基线：继续使用已有 `buildPrompt`、`workerSchema` 与本机 Codex，仅根据提供的资料完成一次文档分析。
- Personal Agent：项目背景与持久记忆、实际抓取的证据、结构化断言、价值判断、需求和行动项。
- 每对先跑 Agent、保存其来源全文和 SHA256，再把**同一份快照**提供给基线。两边收到相同研究任务文字。系统提示、工具流程与输出结构属于产品改造的一部分，因此有意不同。
- 两组 Codex CLI 都禁用工具、宿主 Skills 发现与外部网页访问。素材中的命令不执行，分析资料供给固定。只读 sandbox 之外仍明确关闭执行能力。
- 两个研究案例使用不同项目 ID、相同背景，避免第一个案例的历史输出进入第二个。记忆纠错使用第三个独立测试项目。
- 另做两次明确标记为受控设定的跨会话召回：先记住第一版范围、禁止自动向第三方发送消息、演示团队人数 3 人，再在新请求前把人数纠正为 2 人并明确旧值作废。设定不是用户的真实个人信息，不与真实竞品事实混用。
- 正式研究项目背景固定为 `docs/LEGACY_WORKER.md` 保存的原版 README，不使用已更新为新版功能的 README，两个案例背景完全相同。
- 原型制作与交互、版本、导出单独验收，不加入研究样本分母。

样本不随机，数量小，运行顺序固定，模型存在非确定性。结果只能说明这几次运行中发生了什么，不能推广为平均成功率或宣称统计显著提高。

## 指标定义

| 指标 | 怎么测 | 不能得出的结论 |
|---|---|---|
| 系统执行完成 | 进程成功、得到符合 schema 的产物，记录成功个数/实际样本数 | 内容符合任务要求、事实无误 |
| 任务验收 | 对照任务：研究回答、来源支持、价值判断、可验收需求、下一步行动；逐项记录理由 | 全部类似任务都可完成 |
| 事实错误 | 抽取可核实的事实断言，逐条记录输出原文、来源原文、位置与结论 | 未抽取断言也无错误 |
| 无支持断言 | 资料不能支持的事实声明单列；区分“来源反驳”与“材料不够” | 无支持就一定为假；或不反驳就是真的 |
| 人工干预 | 真实重试、纠正、重新提交的操作次数和原因；受控记忆设置、验收审查单列 | 零补救就不需人工审核 |
| 记忆召回与纠错 | 新请求不再提供三条事实，核对当前事实及旧值已作废 | 一个受控测试代表长期个人化准确率 |
| 引用结构有效性 | 断言引用的证据 ID 是否确实存在 | 断言与原文一致 |
| 调用消耗 | 保留 CLI 原始 NDJSON 中 `turn.completed.usage`；input/cache/output 分别汇总 | Token 可直接换算人民币；cache 与 input 可重复相加 |
| 单任务成本 | 有实际模型路由、适用价格或独立账单才估算；本机订阅为 null | 订阅内调用就是“零成本” |

来源审查由实施/验收人员完成，不冒充独立专家复核。不允许调用另一个模型输出一个分数后，把它当客观实测成绩。

## 断言复核状态

- `supported`：提供材料直接支持该事实，保留相应原文。
- `contradicted`：提供材料直接反驳该事实，是本协议统计的事实错误。
- `unsupported`：事实没有相应证据支持；不自动认定为真或假。
- `unverifiable`：声明需要额外体验、账单或外部数据，当前材料无法验证。

结论或产品方案的好坏不按事实真假计数，应记录其前提和验收理由。官方仓库列出的能力只支持“官方声明提供某能力”，不能支持“该能力可靠”“效果已经提升”等表述。

## 运行与原始记录

先启动本机服务并在设置中选本机 Codex。脚本不会自行购买 API 服务。

```bash
npm run agent:evaluate -- --data-dir data/personal-agent
```

服务地址可用 `--base-url` 调整，工作空间数据库目录可用 `--data-dir` 调整。默认原始档案仍在 `data/evaluations/`，可用 `--artifact-dir` 调整。有工作空间口令时用环境变量 `EVALUATION_PASSWORD`，勿把密码写进脚本或仓库。

每次评测新建三个以“评测”命名的隔离项目，不改用户已有项目。输出在 `data/evaluations/<id>/`，保留：

- `report.json` 与可读 `report.md`；
- 每例完整 Agent 运行、来源正文、抓取时间与哈希；
- 基线请求、schema、Codex NDJSON、stderr、最终 JSON；
- Agent 的逐次调用输入、schema、输出、usage 和 runtime record 副本；内部 reasoning 事件不进入可分享档案；
- 受控记忆的初始值、纠正值和操作记录；
- 来源复核 ledger（完成后为 `review.json`）。

脚本结束时报告仍为 `partial`，验收与事实错误留空，防止将未审查解释为通过或零错误。完成来源审查后导入：

```bash
node scripts/evaluate-agent.mjs --data-dir data/personal-agent --report-id <id> --review <review.json绝对路径>
```

`review.json` 要有 `reviewer`、`reviewedAt`、`cases`。每项 case 以实际 case ID 指定 `baseline` / `agent`，包含 `accepted` 布尔、验收理由和 `assertions`。断言包含 `statement`、`status`、`reason`，建议同时保留 `sourceId`、`sourceQuote`、`outputLocation`。

若失败，不自动把失败样本从分母删掉，也不静默重跑挑最好结果。原始失败保留，补救操作追加到 `interventions`，随后解释处理原因。
