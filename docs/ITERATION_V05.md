# 0.5 迭代：取消记录、待办定位与项目资料

本轮围绕会影响实际使用和研究可检查性的三条链路收尾，不把实现验收当作研究质量提升。

## 本轮变更

取消是一个需要保存记录的过程。模型已经返回的输出与用量应保留，即使随后取消，也不能丢失已报告的消耗或把未报告部分补零。执行和取消共用终态仲裁，任务在收尾保存完后才进入 cancelled；已进入最终业务提交时明确拒绝取消，避免先确认取消再写出成功产物。跨造物服务的取消需要记录上游结果，如果上游已保存版本，要披露这个结果而不是声称整个链路已回滚。

待办按运行 ID 和原始数组索引定位，保留原模型 ID。即使模型给两项相同 ID 或标题，也能编辑正确条目。编辑提交核对条目内容指纹，并另行检查可编辑状态；冲突保留草稿和当前内容，重新确认后才能保存，不自动重试覆盖。

项目资料支持明确导入文本或白名单仓库的已提交说明文档。Git 模式读取固定 HEAD 的文档对象，不扫描文件、不读取未提交修改或任意本机路径；记录提交、Git blob、原始 UTF8 正文与 SHA256、正文提取范围和导入来源。来源状态为 imported，时间为 capturedAt/importedAt，网页 fetchedAt 为空。预览不保存、不调用模型；确认时再次核对指纹，提交改变会拒绝旧确认。资料可明确选入研究、引文和原型依据，但不自动成为确认记忆或已审阅结论。

## 结论与交付边界

本轮修复的是记录可靠性、资料输入与可用交互，证明本机链路能够完成这次真实案例。原来的小样本配对只有一例完整内容可比，旧版 PRD 更详细，不能宣称 Personal Agent 研究质量总体更好。受控记忆召回也不是长期个人化正确率。本轮没有新增质量配对、独立人工评分、全篇事实准确率或成本收益结论。

下一步需求候选已经留在项目中，但背景变化的自动影响分析仍只是此次原型探索；API provider 分支、离线提醒、多人权限、部署及更大样本评测不属于已验证能力。版本在此封存，按用户最新要求不继续下一轮。
