# 0.2 迭代：让项目上下文和后续工作可控

第一版已经完成研究到原型的本机闭环，但还存在实际的使用和执行问题：项目记忆缺少变更历史；后续研究不能主动选用已保存证据；待办只能勾选；首屏返回约 2.5 MB 的内容；同时提交请求可能绕过同项目运行限制。

## 本轮改动

- 项目记忆保留变更记录，可查看旧值、停用和恢复。恢复需要用户确认，不把历史内容自动晋升为当前事实。更新带版本校验，旧页面提交时会提示冲突。
- 记忆变化后使用新的 nanobot 会话上下文；旧会话档案保留。运行层只接收当前有效记忆，审计历史不混入当前事实。
- 新研究可以显式选择本项目已保存的证据。复用保留原抓取时间、原文和 SHA256，并记录来自哪次任务；它不代表本轮重新访问或信息仍然最新。
- 待办可保存备注和截止日期，并从待办继续研究。仍由用户推进，不等于后台提醒或自动对外发送消息。
- 首屏只返回列表与摘要，原文、模型档案、原型源码和评测案例在需要时加载。导出仍保留完整记录。
- 修复同项目和全局任务名额的并发占用，避免重复执行；校验阶段失败会释放名额，执行阶段释放遵循任务实际结束。

## 实测与验收应分开看

[第一版配对评测](EVALUATION_RESULTS.md)保持原样，属于 0.1 的历史记录。其 3/3 受控记忆结果、2/2 补救后研究完成率不被当作 0.2 的新成绩。本轮另行记录自动化协议验证、真实浏览器验收、首屏响应体字节数，以及新增实际模型调用（如有）的原始记录。

协议测试采用隔离数据库和模型 fixture，只证明程序行为，不证明模型推理质量。页面字节减少也不能直接推出网络延迟、模型成本或事实准确率下降。费用缺失继续保留为空，订阅额度不换算现金。

本轮共检查 27 项不同的自动化测试，相关套件均通过；最后增加的最终写入竞态已单独重跑 12 项路由测试。11 项真实浏览器操作验收通过，覆盖记忆纠正/停用/明确恢复、版本冲突保留草稿、来源/原型/评测按需读取、待办日期与备注持久化、跟进草稿、手机布局和控制台。浏览器验收使用单独标记的示例项目，测试用的真实待办字段已恢复，原完成状态未改。

在相同的 6 个项目和 8 个任务上，本机 `/api/agent/bootstrap` 返回内容由 2,525,252 字节减至 104,428 字节，减少 95.86%。这是实际响应体大小，不是延迟或模型消耗评测；完整原文与档案仍由详情和导出提供。之后创建的界面验收项目没有混入此比较。

原始验收、响应体哈希和截图保存在 `data/iterations/2026-10-02-v02/`，交付时单独打包。本轮没有新增真实模型调用，人工验收与开发成本未计价。

## 继续使用

按主 README 启动两个本机服务。原项目、证据、需求、原型和评测数据继续可用；历史项目记忆在需要变更时初始化版本历史。新界面可查看当前有效记忆及变更记录，在新研究中选择证据，在跟进待办中补充安排。

如需要重新核验竞品现状，不要选择旧快照，提供官方页面地址重新取证。新旧快照可以分别保留用于比较，但未抓取就不能称为已更新。

本轮保持单用户、本机执行和人工确认的范围。没有加入长期常驻调度、多用户云服务或完整原型业务后端。
