# 0.4 迭代：需求论证、原型范围与冻结依据

本轮补齐“项目背景／证据主张—候选需求—跟进行动—原型范围”的关联。关联表示形成需求时的依据，不证明需求值得投入；未审阅、未知或争议结论仍可进入明确标记的探索原型。

## 设计与验收范围

新研究需求可引用本次主张的数组索引、研究时项目字段和确认记忆 ID，并写明假设与验证方法。行动明确引用需求索引。旧结果没有这份论证时显示“未建立论证”，不根据共同网页推测关联；模型重复需求 ID 也不造成选择错位。

原型按明确选择的需求生成，而不是点击单卡却生成全部需求。制作前预览范围、当前项目背景、研究时背景、记忆与审阅差异、来源覆盖和风险；提交要核对预览指纹。生成时冻结依据包，后续修改不重写历史。原型是前端探索，不能把工作空间“支持”标签升级为效果担保。

完整输入以 UTF16 字符长度检查预算；预算不是 Token 或现金成本。亦伴的简报与追加提示、造物附加的规则／资料／已有 HTML 分别检查，不静默截断 JSON 或旧代码后继续调用。超限应在模型调用前拒绝并明确调整范围。

新导出应包含当时的需求范围、项目和审阅快照、正文摘录与 SHA；旧原型未保存这些内容时明确未知，不事后伪造成当时输入。

## 已确认的来源覆盖问题

旧取证逻辑把提取正文短于原始 HTML 都标为 truncated，误将清洗转换计为长度截断。新快照分别记录原始／提取／实际提供的 UTF16 长度、方法和转换状态，只有正文上限触发时标长度截断；切断 emoji 时回退到完整字符边界，非法数字实体用替换字符避免孤立代理字符导致 Python 记录失败。

对 0.3 使用的已存 Hermes 原始快照事后对照：原始 HTML 569,598 单位，提取正文与原提供正文均 15,780 单位且相同，未触发 35,000 长度上限。该对照另存为本轮分析，没有重写历史 metadata 或 SHA。原审阅理由追加了更正，旧审阅历史与 0.3 交付包保留。未触发长度截断仍不能保证页面动态内容或已移除部分都被读取。
