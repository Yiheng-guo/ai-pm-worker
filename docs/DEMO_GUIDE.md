# 亦伴 Personal Agent 演示指南

演示重点是围绕同一个项目连续完成研究、判断、需求和后续工作。使用真实模型和来源；空白资料、读取失败、缺证据、模型失败均需如实展示。

## 先体验公开演示

[六步真实页面实拍与离线交互原型](demo/README.md)无需模型授权。下载仓库后，双击 `docs/demo/index.html` 即可切换同一条 v0.5 案例的六步页面，再打开 `prototype.html` 体验示例影响复核。这套静态演示不调用模型，不会发起新的研究或保存到工作空间；原型使用示例业务数据，验证表单是人工记录。完整产品的首次克隆和启动见[公开上手说明](PUBLIC_DEMO.md)。

## 启动

```bash
npm ci
npm run agent:setup
npm run build
npm run agent:start
```

需要把 `product-foundry` 放在亦伴仓库的同级目录，先在造物目录执行 `npm ci && npm run build`；也可通过 `FOUNDRY_DIR` 指定已有造物路径。需要 Node.js 24、Git、uv 和已登录的 Codex CLI。

`agent:start` 同时启动亦伴与造物。打开 `http://127.0.0.1:4310`，原型服务在 `http://127.0.0.1:4320`。本机 Codex 需要提前执行 `codex login`；在设置选择本机 Codex。Python 运行环境用于 nanobot 和公开搜索，模型仍通过已登录的本机 Codex 连接，不从订阅推算单任务现金费用。

## 连续演示

1. 新建项目“亦伴”，填写目标用户、现有范围与约束。可使用本仓库 README 作为背景，但应检查它是否与你当前项目方向一致。
2. 提交真实研究请求：

   > 研究 Hermes Agent 的项目记忆与技能积累，结合亦伴现在的产品范围，判断什么值得放进第一版。保存公开来源，明确官方声明、推断和未知，再形成可验证的需求与行动项。

3. 查看证据原文、抓取时间、链接与断言引用。点击从研究结果进入需求，再回到支持该需求的证据。没有证据的结论应展示为待验证。
4. 对一条需求补充约束或纠正项目记忆，然后发起新会话：

   > 根据我刚刚纠正的项目背景，更新上一份需求的优先级与验收条件，说明哪些判断发生了变化。

5. 从需求页选定一条研究，查看显式论证和待验证假设，选择一条或几条需求。先预览制作范围、当前背景与研究时依据、来源摘录覆盖和审阅快照，确认后生成新探索原型。背景、来源或审阅变动会要求重新预览。新建不继承无关旧功能；API 的显式扩展模式会固定旧版本，并明确旧功能可能保留。原型属于浏览器前端交互，不因此宣称已经构建生产业务系统。
6. 勾选或更新行动项，重新打开项目验证状态仍保存。打开评测报告，查看原版/新版真实样本与原始记录；未测项、失败、无支持断言和不可换算成本都保留。

## 验收清单

| 操作 | 需要看到的结果 |
|---|---|
| 项目背景修改 | 保存后刷新仍保留，后续研究读取当前背景 |
| URL 取证 | 来源正文、时间、哈希或明确失败原因，禁止伪造抓取成功 |
| 证据到需求 | 断言与需求引用可追溯到真实已保存证据 |
| 需求论证 | 新结果显式连接主张、项目字段、记忆、假设和验证；旧结果明确未建立论证 |
| 记忆纠正 | 当前值生效，旧值不继续作为当前事实使用 |
| 行动项更新 | 更新后刷新仍保留 |
| 任务失败/取消 | 状态与错误可见，原始输入仍可查看 |
| 原型 | 可预览、主要交互可用、保存版本、导出能打开 |
| 原型范围和依据 | 新探索只采用选定需求；冻结包保留当时简报，后续变化不重写历史；旧原型未存依据不补造 |
| 评测 | 原始运行记录可下载；空值与失败不会被显示成零或成功 |

## 演示边界

这一版面向单用户本机使用。服务运行时可以保存与续接工作，电脑关机后不能承诺持续执行。没有设置长期常驻服务和调度时，待办不等于后台提醒，任务执行也不等于自动向第三方发送消息。接入线上服务时仍需单独验证云端模型授权、存储、认证和运行方式。
