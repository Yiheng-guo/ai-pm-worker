# v0.7 — 用对话委托亦伴

2026-10-08。这个版本把「用户填写执行表单」改成「用户描述目标，系统选择已接入能力」。它仍是本机个人产品助理，不能声称已成为 Grok Bot 那样的常驻云电脑。

## 体验变化

首页只保留持续对话、输入框和发送。研究/回顾的模式选择、目标输入框、跟进名称/任务/小时/次数表单被移出默认操作路径。项目资料、目标、跟进状态收在「背景与记录」，完整交付与用量按需展开。旧证据、需求、原型、待办及评测工作台保留为辅助入口。

- 「研究这个竞品，结合项目背景判断价值，写需求草稿」：模型理解意图后进入现有研究执行器，读取公开来源，保存真实运行与证据；没有可用来源仍会失败，不生成假证据。
- 「结合我的项目安排本周工作」：自动选择不需要新网页事实的项目回顾。
- 「记住我的目标：…」：明确句式直接保存目标，不需要模型理解调用；其他表达由模型理解，服务端仍检查显式意图。
- 「每天回顾项目进展，最多三次」：提取频率、任务、次数；缺失时追问。先在对话中展示执行范围，回复「确认跟进」启用；10 分钟后过期，无关新消息撤销待确认范围。
- 「暂停全部跟进」：直接暂停，不等模型。其他明确对象由理解器映射当前项目的任务 ID；不能越过次数上限恢复。
- 「根据已有需求生成原型」：选择明确的本项目已完成需求，进入原有造物流程，冻结依据并创建新的前端探索原型。多份需求不明确时应澄清；本版本不自动修改旧原型，也不自动对外发布。

定期任务逐次理解研究/回顾，不能从周期任务新建目标、原型或更多跟进。最小间隔 60 分钟，最多 10 次；到期次数是排队尝试次数，不代表成功完成次数。暂停阻止后续排队，已排队任务仍继续。具体钟点、星期几和每月日历调度不支持，需澄清。

## 实现与成本

nanobot 保留底座；新增严格结构化的 ConversationPlan。模型只输出候选动作，Node 校验动作、参数、当前项目 ID 和现有研究需求后执行。允许的能力固定，不把自由文本转成 Shell 或任意网络写入。任务理解异步执行，不阻塞空间读取与取消；取消后的迟到结果保留已报告用量，不能再保存目标或启动任务。服务重启中断的理解会留下失败记录。

任务理解使用当前项目的背景摘录（1200 字）、目标与约束摘录（各 500 字），不读取完整项目记忆；执行器仍读取原来的有效项目记忆。调度时提供个人目标与最近四轮截断对话，模型理解器每次使用独立会话，避免重复叠加长背景。Codex 的理解调用使用 low reasoning。上下文缩减可能影响指代解析，关键对象不明确时应追问。

自由表达一般多一次模型理解调用；研究/回顾再产生执行调用。跟进也会逐次消耗额度。明确目标、全部暂停和范围确认不额外调用模型。界面分别披露理解与执行用量，费用缺失仍为 null，不能从 Token 编造现金账单。

## 公开页面的边界

GitHub Pages `/personal/` 是对话交互示例：目标、有限次范围确认与暂停只保存在浏览器；规则识别只是演示脚本，不是线上 LLM。公开页面不调用模型、不读取私人项目、不执行定时任务。真实版本在本机 4310，造物在本机 4320。历史 `/tutorial/` 视频仍标为 v0.6，并提示切换到当前对话版，不能冒充新版录像。

参考：[Grok Bot 官方说明](https://docs.x.ai/grok-bot/overview)，其中消息委托、连续上下文与对话内进度是设计参考。没有复现其云电脑、应用连接器或全天候执行环境。邮件、日历、购买、电脑操作尚未接入，模型不得宣称已完成。
