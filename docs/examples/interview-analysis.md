# 实际模型验收样例

来源：本机 Codex 实际调用。输入为人为编写的示例访谈，不是真实用户研究。

## 1. 材料与证据边界

[来源 1] 任务中提供的示例访谈转述：用户 A 说每周花两小时整理访谈，不知道结论对应哪句话。

未提供外部资料、完整访谈记录或用户逐字原话。因此，以下不将转述包装为直接引语；两小时属于用户自述，未经计时验证。

## 2. 访谈主题与痛点

| 主题 | 来源支持的事实 | 痛点解读与边界 |
|---|---|---|
| 整理投入 | 用户 A 自述每周花两小时整理访谈。[来源 1] | 整理存在时间投入；这是否构成明显负担、主要耗时环节是什么，仍需确认。不能仅凭两小时判断效率低下。 |
| 结论追溯 | 用户 A 不知道结论对应哪句话。[来源 1] | 结论与原始语句之间的对应关系不清晰。可能影响核查和复用，但具体影响尚无证据。 |

两个主题可能相关，但现有材料不能证明“寻找原话”是整理耗时的主要原因。

## 3. 可验证需求

以下是从痛点推导的候选需求，尚未获得用户确认。验收条件是拟议方案，不代表功能已实现或验证通过。

### 需求一：能够追溯结论的依据

- **需求表述：** 用户查看一条访谈结论时，能够找到支持该结论的原始语句及必要上下文。
- **依据：** 用户 A 不知道结论对应哪句话。[来源 1]
- **验证方式：** 请用户拿一条近期结论，演示如何找到依据；再用带证据关联的原型完成同类任务，观察能否准确定位并判断原话是否支持结论。
- **拟议验收条件：** 标注为有依据的结论具有可访问的原文关联；关联保留原始语句及上下文，不以改写摘要冒充原话；没有充分依据时明确标注“待核实”。
- **不确定性：** 用户需要句子定位、时间戳还是记录段落；一条结论是否需要跨多次访谈关联证据。

### 需求二：减少重复整理投入

- **需求表述：** 在保留可核查依据的前提下，减少从访谈材料到可用结论的重复整理工作。
- **依据：** 用户 A 自述每周花两小时整理访谈。[来源 1]
- **推断边界：** 希望节省时间是合理假设，但用户尚未明确表达期望节省多少时间或愿意改变哪些流程。
- **验证方式：** 先记录当前整理步骤与各步骤耗时，再用内容规模和复杂度相近的材料比较现有流程与候选方案，纳入人工复核和返工时间。
- **拟议验收条件：** 整理总耗时低于可比任务基线，同时结论的证据支持程度不下降；具体改善目标应在基线采集后确定。
- **不确定性：** 每周材料量、整理频次、工具、交付格式，以及耗时是否集中于转写、归类、总结或核对。

## 4. 验证记录与判断标准

以下均为验证计划，目前没有实测结果。

| 观察项 | 定义 | 当前状态 |
|---|---|---|
| 整理总耗时 | 从开始处理材料到形成可用结论的实际工作时间，包含复核与返工 | 仅有每周两小时的自述，缺少任务量及计时记录 |
| 证据定位成功率 | 正确定位支持原话的结论数 ÷ 被要求追溯的结论数 | 未测量；需人工判断原话是否支持结论 |
| 证据定位耗时 | 从查看指定结论到找到并确认支持原话的时间 | 未测量 |
| 结论证据支持率 | 经复核有充分原文支持的结论数 ÷ 被复核结论总数 | 未测量；用于避免以牺牲准确性换取速度 |

不能把“存在原文链接”直接视为“结论有充分依据”，还需检查语义和上下文。

## 5. 后续访谈问题

1. 请用最近一次访谈演示整理过程：两小时分别花在哪些步骤？
2. 请展示一条找不到对应原话的结论：当时怎样寻找，最终有什么影响？
3. 找到原话后，你还需要哪些上下文才能确认结论成立？
4. 如果只能先改善一项，你更希望减少整理时间，还是更容易核查结论？为什么？
5. 每周通常整理多少份、什么形式的材料？怎样才算整理完成？

## 6. 当前结论

现有材料足以提出“结论可追溯”和“减少整理投入”两项待验证需求，其中结论追溯问题的证据更直接。尚不足以确认普遍性、最终优先级、收益幅度，或认定自动总结就是合适的解决方案。
