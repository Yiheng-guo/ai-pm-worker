# 0.3 迭代：从引用关联到逐条证据核验

仅有来源 ID 和链接不能证明结论正确。一个来源也可能被反向解读、截断、过时，或者只是公开功能声明。本轮把模型主张、原文摘录匹配和审阅者判断分开保存。

## 本轮能力

每条主张可带模型提供的连续原文摘录。系统针对这次研究实际使用的已存正文检查摘录、计算定位并固定来源 URL、原始 SHA256、正文哈希和抓取时间；原文的发布日期没有核实时保持未知。

匹配成功只说明该文本存在，不会自动标记结论正确。审阅者可以标注“支持”“矛盾”“待核实”或撤回为未审阅，填写理由，并保留修订历史。主张或来源改变时，旧审阅失效而不是继续充当有效判断。

模型原文、候选引文和原始调用记录保持独立。旧版本没有提供引文的主张显示“未提供摘录”，不会被事后改写为模型失败。模型生成的虚构或不匹配引文会明确暴露，不能被静默修补后当作原输出。

工作空间用户的审阅与 Codex 协助复核分别记录。由本任务实施者填写的结果标为 `agent-assisted`，不声称经过独立人工或专家审核。

## 验收原则

固定测试包含公开声明、反向解读、虚构摘录、正文截断、历史价格、来源冲突、当前记忆冲突和资料不足。合成材料只验证协议与程序行为，不当作模型成绩；不得靠全部回答“未知”缩小分母而获得虚高准确率。

第一版的真实配对评测和 0.2 的功能验收继续保留原样。新增模型调用（如有）另存来源、输入、输出和真实返回用量；不把新能力自动当作质量提升，也不从订阅额度换算现金。

## 使用边界

审阅功能辅助产品经理核查依据。来源摘录不能替代竞品实际安装、业务指标试验、当日价格重新取证或独立专家验证。复用的快照保留原抓取时间，不能说成本次最新核验。

这套摘录定位针对研究实际使用的公开来源。私人项目记忆的确认另走记忆版本历史；没有公开来源的私人事实不能为了获得“支持”标记而伪造公开引文。

## 程序验收

本轮完整 `npm test` 共 34 项通过，包括真实 nanobot 流程接线的本地协议 fixture，以及八类对抗输入、Unicode 边界、来源篡改、并发审阅、指纹失效、原始结果不变和导出。fixture 不消耗模型额度，也不是模型真实效果测试。前端 TypeScript 与生产构建通过。

随后补充了实际 Python 输出 `start:null` 的兼容测试，审阅 8 项通过。严格 provider schema 和兼容旧结果的解析采用两套契约：新 schema 的每个嵌套对象要求所有字段，允许空数组或明确 null；历史解析仍接受缺省引文。模型输出示例还由独立 JSON Schema 验证器核对。
