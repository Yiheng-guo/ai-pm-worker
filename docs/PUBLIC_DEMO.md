# 公开演示与本机上手

先用[在线六步演示](https://yiheng-guo.github.io/ai-pm-worker/)或[可点击探索原型](https://yiheng-guo.github.io/ai-pm-worker/demo/prototype.html)了解产品，无需登录、无需模型调用。[GitHub 演示文档](demo/README.md)可以直接查看图片；下载仓库后，双击 `docs/demo/index.html` 打开可切换的离线演示。

公开静态演示与完整产品分开：静态站展示已保存案例，探索原型只操作浏览器示例数据；它不能替你发起新的竞品研究、保存工作空间、调用造物生成或执行待办。

## 完整产品：克隆两个仓库

需要 Node.js 24、Git、uv、Codex CLI，以及自己的模型授权。亦伴默认启动脚本同时启动造物，两仓库放在同一个父目录。第一次安装 nanobot 需要联网，固定版本为 0.3.5，提交 `d0d0a44e57632c3d269e511339cff7ddb698e62e`。

```bash
git clone https://github.com/Yiheng-guo/ai-pm-worker.git
git clone https://github.com/Yiheng-guo/product-foundry.git

cd product-foundry
npm ci
npm run build

cd ../ai-pm-worker
npm ci
npm run agent:setup
npm run build
codex login
npm run agent:start
```

打开 `http://127.0.0.1:4310`。这是你的本机地址；造物服务在 `http://127.0.0.1:4320`。如造物不在同级目录，可设置 `FOUNDRY_DIR` 指向自己的造物仓库。运行模型任务会消耗自己的授权额度；本机 Codex 的订阅不能直接换算成每次调用现金费用。

首次克隆是空白工作空间，不会恢复作者的项目数据库、历史研究或实测记录。公开截图和探索原型帮助理解流程；你需要在本机建立自己的项目，使用自己的资料和授权开始研究。

## 第一次操作

1. 建立项目，填写真实目标、现有范围和约束；确认一条确实适合长期保留的记忆。
2. 提交一个范围明确的研究请求，优先提供竞品的公开 HTTPS 来源链接。公开搜索可能失败，失败会保留，不能用一次成功假定所有站点都可读取。
3. 查看来源原文与模型摘录，核对主张，保留事实、推断和待验证项的区别。
4. 从需求草稿选择一条需求，预览制作范围与依据，确认后交给造物生成探索原型。
5. 在待办中记录验证进展。需要真实配对评测时，再按照[评测协议](EVALUATION_PROTOCOL.md)运行；评测会真实消耗模型额度。

完整连续流程与失败验收见[演示指南](DEMO_GUIDE.md)。请勿把研究示例的需求与结论直接当成自己项目的需求。

## 当前边界

- 完整产品面向单用户本机；关机后没有长期执行，也没有离线自动提醒。
- 造物生成浏览器前端原型，适合验证交互；它不会自动搭建完整生产业务后端。
- 示例原型的影响识别采用显式关联规则，不代表完整产品已经具备自动语义影响分析。
- 工作空间数据库和 `.runtime/` 私有会话不进入 Git。公开演示仅包括已检查的产品机制截图和示例前端；不要把自己的运行资料直接提交到公开仓库。
- 单次案例展示链路可运行，不能证明普遍准确率、记忆可靠性或成本收益。未测项和未报告成本保持未知。
